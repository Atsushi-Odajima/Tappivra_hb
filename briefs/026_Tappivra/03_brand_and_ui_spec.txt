商品 #026 Tappivra — ブランド・UI仕様 1.0
2026-10-04

01. デザインの目的
画面のスクリーンショット自体を主役にする。アプリの装飾がデモの内容と競合しない編集道具として設計する。
白と黒を主体に、青は「今選んでいる場所」、水色はその補助に限定。
映画的な背景、青いサイドバー、大面積グラデーション、紫、発光、人物写真、架空KPIを使わない。
受賞を主張しない。静かな編集デザイン、精密な整列、読みやすさ、操作の発見しやすさを目標にする。

02. ロゴと表記
製品表記：Tappivra。読み：タッピヴラ。略記や別商品名をUIへ混在させない。
マーク：開いた画面枠と、その中の小さい操作点を表すオリジナル幾何形状。
基本は黒、操作点に青。小さいアイコンでも輪郭が残るようにする。
横長PNGは透過。明るい背景に配置。暗背景は同梱logo_horizontal_dark.pngを使う。
最小表示幅：横長ロゴ132 CSS px、マーク24px。周囲の余白はマーク高さの1/4以上。
ロゴを傾けない・潰さない・別の青/紫へ変えない。再作図せず同梱SVG/PNGを使用する。

03. 配色トークン（HEXと用途）
canvas       #FFFFFF  主背景／PWA背景
page         #F7F8FA  作業領域外側
surface      #FFFFFF  パネル・カード・入力
ink          #15171B  本文・見出し・主ボタン背景
muted        #5D6470  補助文字・説明
subtle       #747C88  日時等。小文字で使用時は実コントラスト確認
border       #DDE1E7  罫線・カード境界
borderStrong #A7AFBB  入力欄・区切り強調
accent       #2563EB  選択枠・リンク・フォーカス・操作点
accentSoft   #DFF3FC  選択補助面。広い面には使用しない
error        #B42318  入力/出力エラーの文字・アイコン
errorSoft    #FEF3F2  エラー補助面
success      #126C4C  保存完了等の文字（チェックと文言併用）
warning      #8C5A13  容量・領域重なり警告

通常画面の彩色面積は目安5%以下。エラー状態の警告面まで機械的に5%以内にしなくてよい。
主ボタンはink背景＋白文字。青ボタンを並べない。
青(#2563EB)は白背景との小文字コントラストも確認する。水色面に白文字は使わない。
装飾の灰色罫線に文章のコントラスト基準を適用したと誤報しない。本文と操作文字を優先する。

04. 書体・階層
英数字：Inter。日本語：Noto Sans JPを候補とし、なければYu Gothic UI／Meiryo／システムUIへ。
表示サンプルにはNoto Sans CJK JP系を使用。製品ビルドでは採用する実ファイルのライセンスを確認する。
フォントファイルは今回ZIPに含めない。販売用同梱を行う場合、開発者が正規配布元から取得しライセンス添付。
ビューアーの単独HTMLはOSフォントで動作し、外部フォント読み込みを要求しない。

見出しXL：32px / weight600 / line-height1.25
画面見出し：24px / weight600 / line-height1.35
パネル見出し：16px / weight600 / line-height1.5
本文・入力：16px / weight400 / line-height1.6
表・一覧：14px / weight400 / line-height1.5
補助：12px / weight400 / line-height1.5（長文の本文には使わない）
数字カウントは等幅数字。色や大きさで架空の達成率を作らない。
長いファイル名は省略表示＋完全名を確認できるフォーカス/詳細を用意。スクリーンリーダーは完全名。

05. 寸法とレイアウト
8pxスケールを基本：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
PCエディターは画面全幅、最小推奨1280×720。トップバー64px。
左ステップパネル216px、右プロパティ280px、中央は残り幅。境界1px、面は白。
中央の画像領域はpage色で囲み、24px以上の余白。画像の周囲へ飾りの機器モックを置かない。
ライブラリー最大幅1120px、24px外余白、3列カード（最低280px）。
1024〜1279px：右パネルを閉じられるドロワーに。編集画像を最低480px確保。
1024px未満：エディター表示は案内のみ。閲覧用ビューアーへ誘導。スマホ編集対応と広告しない。
ビューアーは最大1100px、モバイル横余白16px、本文16px。
カード角丸12px、モーダル16px、ボタン8px、入力8px。
影はモーダルのみ0 12px 36px rgba(21,23,27,0.12)。通常パネルは影なし＋罫線。

06. ボタン・入力・選択
主操作：高さ44px以上、左右16px。黒地白字。hoverは#2C3037、activeは#060708。
副操作：白地、1px borderStrong、ink文字。hoverはpage。
フォーカス：accent 2px＋offset2px。outlineを削除しない。
無効：#E6E9EE面、#747C88文字、disabled属性、無効理由を近くに表示。
危険操作：通常主操作と離し、赤文字＋明示確認。赤を装飾に使わない。
入力：最小44px、上下10px左右12px、常時label。placeholderをlabel代わりにしない。
エラーは入力直下の赤アイコン＋文、aria-describedbyで関連付ける。
選択中ステップ：左3px accent線、薄い水色の小さい番号バッジ、inkのタイトル。全面青にしない。
チェックボックス・ラジオ：タッチ領域44px、可視チェック20px程度。

07. 画面A ライブラリー
上部にロゴ、中央寄りに検索、右に黒い「デモを作る」。
カードは名称、静的サムネイル、更新日時、ステップ数、バックアップ状態。
空：「最初の操作デモを作りましょう」「画面画像を5枚ほど用意してください」。主ボタン1つ。
読み込み：既存カードの大きさを保つ骨組み。0.3秒未満の点滅を避ける。
検索0件：「一致するデモはありません」「検索条件をクリア」。

08. 画面B エディター（assets/ui_editor.png）
ヘッダー左：戻る／ロゴ。中央：編集可能なデモ名称と保存状態。
右：副「プレビュー」、黒「書き出し」。
左：ステップサムネイル＋番号と名称、末尾「画像を追加」。ドラッグ以外に上下ボタン。
中央上：「クリック箇所を追加」「隠す」「フィット」。中央に画像、選択領域は2px青枠と四隅ハンドル。
右：「クリック箇所」、名称、案内文、移動先セレクト、座標4項目。下部に削除。
画像が未選択：「左のステップを選択してください」。
保存中：「保存中…」、成功「保存済み」、失敗「保存できませんでした。もう一度保存」。
保存失敗をトーストだけで消さず、ヘッダーに保持する。

09. 画面C 画像確認・黒塗り
画面または広いモーダル。画像中央、左上に画像番号、右に「隠す」「確認して保存」。
塗りつぶしは黒100%。ぼかし・薄い透過で秘密情報を隠した扱いにしない。
チェック文：「この画像に公開したくない情報がないか確認しました」。
非対応：「この形式は使えません。PNG・JPEG・静止WebPを選んでください」。
サイズ超過：「1枚あたり10MiBまでです。画像を縮小してから追加してください」。
同じサイズ上限をUIと実際の検証で共有する。

10. 画面D 閲覧／画面G モバイル（assets/ui_mobile.png）
トップにデモ名、右に目次。青い点は選択だけ。
画面タイトル→画像→短い説明→代替ボタンの順。
モバイルは画像の細かいボタンが触りにくくても、下に同等の44pxボタンを表示する。
例：「新規作成を開く」。別の分岐は「一覧に戻る」等のラベルを付ける。
固定下部バーは「戻る」「最初から」。safe-area-inset-bottomを確保する。
「ステップ2/5」を達成率と誤表示しない。分岐時は現在の画面名と訪問履歴を使う。
初回PWA：「閲覧データを開く」「サンプル」。ファイル読込中は取消可能な進捗。
読み込みエラー：「閲覧用データではありません。作成者へ閲覧ZIPをご依頼ください」。
保存容量不足：「端末に保存できません。今回は保存せずに表示できます」。

11. 画面E 出力チェック
上からデータ範囲、検査項目、容量、形式選択、保存先。
未確認は「要確認」、失敗は具体的な理由と「該当箇所へ」。全てを丸いグラフにしない。
成功：「書き出しの準備ができました」。ファイル保存完了後のみ「保存しました」。
警告：元画像ではなく加工画像のみ、内部メモは閲覧出力に含めない旨。
編集バックアップは「内部メモを含みます。顧客配布用ではありません」と明記。

12. 動きとアクセシビリティ
hover/選択120ms、ドロワー150ms。prefers-reduced-motionで移動効果なし。
ステップ切替は派手なスライド／拡大演出を行わない。
色だけで成功/失敗を示さない。見出し順、label、button名、キーボード到達をテスト。
200%文字拡大で説明文とボタンを切らない。スマホinput16px以上。
ホットスポットの座標精度は01仕様の計算に従い、モックの絶対ピクセルへ固定しない。

13. ブランドボードのルール
上部：同梱ロゴ。すぐ次に一般向け3行。
「アプリの操作を説明したい制作者へ。」
「画面画像から、押して進めるデモを作成。」
「実アカウントや録画なしで、使い方を伝える。」
機能ラベル：画像を並べる／押す場所を指定／秘密を隠す／HTMLで渡す。
主要画面と小さいPWAビューアー、配色、タイポグラフィ。人物写真や英語の煽りコピー不要。
「UI設計イメージ・未実装」を入れ、稼働中アプリの証拠として誤認させない。
横長ロゴとPWAアイコンはここに貼るものと単体PNGを同じ元SVGから作る。
